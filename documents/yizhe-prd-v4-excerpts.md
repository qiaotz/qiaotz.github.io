# 医者（原名研医志）｜产品需求文档原文节选

来源：研医志医学考研智能学习系统产品需求文档 V4.0，2026-07-30。

这是历史需求规划，不代表全部功能已经实现或通过验收。收录下列 7 个完整小节，未改写正文；不是完整 PRD。

### 1.1 问题陈述

当前产品已经具备题库、历年真题、课程、错题、会员积分和运营后台等基础能力，但学习行为仍以资源浏览和单点做题为主。用户难以知道今天该学什么、学习后如何验证、何时复习、错题何时才算真正解决；内容、作答、掌握状态、笔记和 AI 也缺少统一的生命周期。

此前 V3.0 描述了较完整的产品愿景，V3.1 为保证首期可执行性收敛为 P0 免费封测基线。仅使用 V3.1 会造成“首期开发文档等于完整产品需求”的误解，因此需要由本文件统一全生命周期目标，并继续用阶段细则控制每期范围。

---

### 1.3 产品定位与原则

**产品定位：** 面向 306 西医综合、307 中医综合及后续医学考试方向的智能学习系统，帮助用户形成可执行、可验证、可复习的长期学习闭环。

**产品使命：** 让用户在任何时刻都能回答“现在学什么、为什么学、学完如何验证、何时再复习、错误是否真正解决”。

统一原则：

1. 五阶段是固定产品心智，今日计划负责组织，不成为第六阶段。
2. 推荐不等于强制通关，用户可自由进入任一阶段。
3. “已学习”和“已掌握”必须分开表达，不展示伪精确掌握百分比。
4. 一次浏览、一次答对或 AI 判断均不能直接形成稳定掌握。
5. 所有状态变化可追溯到内容版本、题目版本和学习证据。
6. AI 不替代审核教材，不提供真实诊疗建议，不直接修改正式掌握状态。
7. 付费不改变标准答案、解析、个人笔记和既有学习历史的真实性。
8. 每个阶段都必须能独立灰度、降级和回滚，不删除历史事实。

### 2.1 用户角色

| 角色 | 核心目标 | 主要约束 |
|---|---|---|
| 首次备考用户 | 建立知识框架并知道每天先做什么 | 对考试范围和复习方法不熟悉 |
| 强化期用户 | 通过练习验证薄弱点并提高稳定性 | 学习资源分散、错题重复发生 |
| 冲刺期用户 | 用模考、到期复习和高频错题提高得分 | 时间紧、任务优先级冲突 |
| 在职或二战用户 | 在有限时间内持续推进并跨设备恢复 | 时间碎片化、容易中断 |
| 内容编辑 | 导入、编辑和维护课程、题目、解析及知识点 | 不拥有最终医学发布权 |
| 医学审核员 | 对内容版本和 AI 评测集进行医学审查 | 高风险内容必须双人独立审核 |
| 版权/运营人员 | 管理权利证据、发布集合、权益和活动 | 不得绕过医学审核和审计 |
| 客服/管理员 | 处理账户、权益、退款和数据请求 | 按最小权限访问，不得修改历史事实 |

### 2.2 整体信息架构

底部导航固定为五个入口：预习、学习、做题、复习、改错。公共顶部区域承载考试方向、今日计划、笔记和个人入口。

- 专项练习、智能组卷、历年真题、题组和模考统一归入“做题”。
- 首页能力迁入“今日计划”，不保留独立首页 Tab。
- AI 不设置独立一级入口，只在当前内容、题目、错题、复习或笔记上下文出现。
- 择校、招生、复试和 AI 面试不进入新版导航，旧数据只读保留，是否形成独立产品另立决策。
- P1/P2 页面只有在对应阶段发布门禁通过后才注册路由；P0 不显示灰色入口或“敬请期待”。

### 2.3 全生命周期用户旅程

```text
获知产品 → 微信登录 → 同意协议与隐私政策 → 选择考试方向
→ 设置考试日期、备考阶段和每日时间 → 生成今日计划
→ 预习 → 学习 → 做题 → 复习 → 改错
→ 学习报告与计划调整 → 连续学习与召回
→ P1 会员权益体验 → P2 购买/续费/退款/积分
→ 导出个人数据或注销 → 按保留策略删除/匿名化
```

生命周期规则：

1. 新用户完成首次设置后直接进入最高优先级可执行任务。
2. 老用户优先恢复未完成沉浸任务；恢复失败时进入可解释的替代任务。
3. 每个阶段完成后只突出一个推荐下一步，用户仍可自由切换。
4. 跨日、退后台、冷启动、Token 过期和内容撤回均不得静默丢失草稿或已确认学习事件。
5. 召回通知必须基于用户授权、到期任务或明确订阅，不发送诊疗暗示、虚假紧迫或付费恐吓。
6. 会员到期只影响增强权益，不删除笔记、历史作答、错题或已经获得的学习事实。
7. 注销前提示影响，支持导出；注销完成后按法规、合同和审计要求删除或去标识化。

### 2.4 五阶段核心闭环

#### 2.4.1 预习

**用户故事：** 作为备考用户，我希望在正式学习前快速理解章节结构并发现薄弱点，以便把时间用在真正陌生的内容上。

**统一完成条件：**

- 展示章节目标、知识结构、重点与诊断微测。
- 预习只产生“接触、陌生、模糊或错误理解”证据，不直接标记掌握。
- 未提交诊断前不得显示答案；提交后只显示审核答案和解析。
- P1 可根据历史证据调整预习顺序；P2 Agent 只能建议顺序，正式任务由计划规则确认。

#### 2.4.2 学习

**用户故事：** 作为备考用户，我希望使用审核课程和讲义补齐薄弱知识，并保存自己的理解，以便后续验证和复习。

**统一完成条件：**

- P0 课程阅读达到 `maxReadPercent >= 80%` 且累计前台有效时间达到 60 秒，才记录一次有效学习。
- 每个 P0 学习单元配置 3–5 道关键节点微测题；不足 3 题时不得伪装成正式微测。
- P1 加入 AI 笔记整理、OCR、结构化对比和 TTS；原始输入永久与 AI 派生版本分开。
- P2 可由 Agent 推荐学习材料，但只能使用当前有权访问且审核有效的版本。

#### 2.4.3 做题

**用户故事：** 作为备考用户，我希望用不同题型验证理解并获得可信解析，以便发现知识漏洞而不是只记答案。

**统一完成条件：**

- P0 支持单选、多选、分层提示、即时判题和标准解析。
- 未提交前不得返回正确答案、等价答案文本或逐项排除结论。
- P1 增加题组、病例串题和完整模考，交卷前冻结题目版本与计分规则。
- P2 增加受约束智能组卷和预测；AI 生成题仅能进入草稿和审核流程，不能直接进入用户题库。

#### 2.4.4 复习

**用户故事：** 作为备考用户，我希望系统按到期时间组织主动回忆和验证，以便把短期记忆转为稳定掌握。

**统一完成条件：**

- P0 使用六级掌握状态，并生成 D+1、D+2、D+3、D+7、D+14、D+30 复习任务。
- 复习结果必须记录提示、笔记、解析和 AI 使用情况；有辅助的正确回答降低证据权重。
- P1 提供主动抽问、追问、记忆卡片、语音回答和易混知识对比。
- P2 可优化间隔和任务组合，但新算法必须版本化、可回放、可影子比较。

#### 2.4.5 改错

**用户故事：** 作为备考用户，我希望确认错误原因、完成补学并经过间隔验证，以便真正解决错题而不是把它从列表中隐藏。

**统一完成条件：**

- 错题必须经过错因确认、24 小时后原题复测和同类题验证后才能清除。
- 再次答错创建新的 WrongCase 实例并关联旧实例，不篡改历史。
- P0 错因由用户确认，AI 不自动决定。
- P1 可给出错因建议和补学材料，只有用户确认后才能写入正式记录。
- P2 可分析跨章节错误模式并建议训练计划，但不能覆盖事实记录。

### 5.5 测试计划

| 类型 | 必测范围 |
|---|---|
| 单元测试 | Mastery、Review、DailyPlan、WrongCase、权益、订单、退款、积分及所有状态机 |
| 属性测试 | 重复、乱序、晚到、部分失败、投影重建、幂等回放和账本守恒 |
| API 契约 | OpenAPI、鉴权、对象权限、幂等、分页、错误码、乐观锁和版本兼容 |
| 集成测试 | Attempt 到事件/掌握/错题/复习/Outbox；支付到权益/账本/对账；AI 到引用/反馈/扣额 |
| MySQL 实库 | 唯一约束、行锁、并发 upsert、迁移重跑、财务状态机和 Outbox 重放 |
| 客户端 E2E | 登录→设置→今日计划→五阶段→报告；P1 模考/智能笔记；P2 购买/退款/Agent 确认 |
| 弱网与离线 | 退后台、冷启动、跨日、Token 过期、断流、重复同步、内容撤回和版本冲突 |
| 安全 | 串权、越权、支付伪造、对象存储、注入、提示注入、敏感数据和机构隔离 |
| AI 评测 | 医学错误、引用、拒答、检索、OCR/TTS、Agent 工具权限、生成题审核 |
| 灾备 | 备份/binlog 恢复、Outbox 重放、投影/索引重建、财务对账恢复 |
| 人工可用性 | 306/307、不同备考阶段、iOS/Android、字体放大、读屏和无协助核心路径 |

每个 `FR-*` 必须映射唯一测试 ID；参数化子用例可共用 ID，但不得用未登记别名代替追踪。
